# v0.5.75

Web UI history can now recover individual message and tool dates from saved
Codex session logs when the runtime's item-history API is unavailable. Codex
0.162 advertises that API in its schema but returns "not supported yet," which
caused v0.5.74 to keep displaying the shared turn-start date.

The worker indexes saved event dates in its existing SQLite database. It scans
logs incrementally, reuses completed work after restarts, and gives selected
sessions a bounded recent-history scan. Background indexing has a shared budget
so large session stores do not trigger full repeated history scans. The index
stores timing and identity metadata, with content digests for matching; it does
not store another copy of conversation text or attachments.

Recovered dates are labeled **Recorded**. Synthetic message IDs are matched
within their original turn using Codex's reconstruction rules; repeated messages
are checked against their original order and counts. Missing, incomplete or
ambiguous matches retain the explicit **Turn started** fallback.

Update the gateway and workers, then reload the Web UI. Older history may catch
up as its bounded index backfill progresses.
