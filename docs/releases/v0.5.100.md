# v0.5.100

Telegram bots keep independent session selections. Use `/tgsessions` in each bot
to follow different conversations; bots selecting the same session both receive
its output. Questions remain shared across enabled, authorized bot chats.

Requests containing several questions now send each follow-up to every bot,
including bots following another session. Answer from any copy, and all original
copies are edited to show **Question:** and **Answer:** without their buttons.
Delayed callbacks cannot overwrite an accepted answer. Reopened questions after
a definitely failed submission stay interactive, and fresh Telegram or terminal
answers replace retained summaries correctly. Late message deliveries also
receive the answer edit.

Each bot in Admin now has an **Inherit selected session name** checkbox, off by
default. Enabling it shows **Original name · Session name**, using the gateway
owner's private-chat selection. Switching or renaming that session updates the
bot's default Telegram display name; disconnecting or turning the option off
restores the saved original. Usernames and routing identities remain unchanged.
Names respect Telegram's length limit and the gateway's outbound redaction.

Name changes run in the background, respect Telegram retry limits, and stop
when the bot is disabled or its webhook has moved. Migration 026 preserves the
preference, original name, and uncertain remote-update state across restarts so
lost API responses cannot prevent restoration. Language-specific Telegram names
can take precedence over the updated default name.

The bot-removal dialog retains the bot's username and a **Delete in BotFather**
link after its gateway connection is removed. Permanent Telegram deletion still
requires the owner's confirmation in BotFather; removing a gateway connection
does not delete the Telegram bot. Worker sessions and project files remain.

Coverage includes independent bot routing, shared multi-question requests,
delayed delivery, retry recovery, name synchronization and cancellation,
authorization boundaries, migration, and desktop/mobile Admin flows.
