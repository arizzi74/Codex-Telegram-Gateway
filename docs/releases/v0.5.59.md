# v0.5.59

This release fixes worker updates that could remain blocked after a canceled or
timed-out Codex metadata request.

## Worker update safety

- Canceled metadata reads no longer leave the runtime permanently marked as
  having pending or unconfirmed requests.
- Canceled requests are tracked individually. A matching protocol rejection can
  settle a canceled mutation, but a late success alone does not prove accepted
  work has completed. Unconfirmed mutations, active turns, unanswered approvals,
  queued work, and unknown protocol activity continue to prevent an unsafe restart.
- Worker status includes bounded RPC blocker diagnostics with sanitized method
  names, request start times, and pending/writing/unconfirmed phases in
  `rpc_update_safety`. Diagnostics exclude prompts and request payloads.

## Upgrade

An older running worker that already has a permanent blocker needs a controlled
restart to load the correction. Finish its turns and approvals, then follow the
[worker recovery instructions](https://github.com/arizzi74/Codex-Telegram-Gateway/blob/v0.5.59/docs/installation.md#updating-running-workers)
from a separate terminal or SSH shell. The Linux procedure pauses scheduled and
requested updaters, preserves queued requests, and restores the worker and its
previous timer state even if the manual update fails.
