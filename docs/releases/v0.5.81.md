# v0.5.81

Revoked workers no longer appear in the Codex Web UI sidebar or Telegram session
pickers. The live inventory removes their sessions when a worker is revoked;
enabled workers remain visible even when offline or before their first session.
The operations console keeps revoked records for inspection. Sessions and files
on the worker are not deleted.

The operations console now provides optional **Password sign-in** settings.
After initial passkey enrollment, an administrator can enable, change or disable
a username/password for the same account. Both the operations console and the
desktop/mobile Codex interface offer password login and renewal alongside
passkeys. Password access remains disabled until configured.

Passwords use salted Argon2id hashes. Password login has separate per-client
and global rate limits and bounded hashing concurrency. Both sign-in methods
share the existing secure cookies, eight-hour session expiry, recent-authentication
requirements, browser-session revocation, and renewal of notification and draft
ownership. Changing or disabling a password revokes its existing sessions while
preserving passkey access. At least one passkey remains available for recovery.

The gateway applies SQLite migration 021 automatically. Workers do not need an
update for these interface and authentication changes.
