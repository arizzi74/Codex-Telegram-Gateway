# v0.5.82

Fresh worker setup visibly echoes both the enrollment URL and any replacement
URL so you can check pasted or typed input.

On Linux, setup now asks **Restrict this worker service?** before redeeming the
URL. **Yes** is the default and enables `PrivateTmp`, `PrivateUsers`, and
`NoNewPrivileges`, blocking sudo. **No** disables all three and uses the
account's existing permissions and sudo rules; it grants no new privileges.
This local choice determines installed access, overriding the access returned
by enrollment. The admin dialog retains its selection for older installers.

macOS skips the systemd question and uses normal account permissions through
launchd. Recovery resumes with the saved choice; existing installations and
prepared configurations retain their settings without the new question.
