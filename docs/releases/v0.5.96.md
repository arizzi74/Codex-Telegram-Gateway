# v0.5.96

The Telegram audio settings in Admin now offer two local response engines:
**Piper / Miro** and **Qwen3-TTS 1.7B quantized**. Each option explains its
languages, expected quality, model storage, measured RAM, and generation speed.
Piper is recommended for fast CPU replies; Qwen needs a larger memory budget
and takes substantially longer on the reference ARM host.

Applying a selection downloads the chosen signed native helper and pinned,
checksum-verified models, then tests the voice before saving settings. Successful
switches activate the selected engine and remove the unused managed speech
engine and models. Failed preparation or settings saves keep the previous voice
available. Existing Pocket TTS installations retain their current settings until
an administrator explicitly selects one of the new options.

Both engines keep a resident model between replies. Qwen includes portable and
optimized CPU builds, selected only when the processor supports the required
instructions. Reapplying Qwen settings avoids loading two copies of its model.
Generated recordings remain in memory. Telegram still shows typing until audio
is ready, then sends the final text followed by audio.

Optional native helper bundles are published for Linux and macOS on amd64 and
arm64 and are covered by the release's signed checksum manifest. They require
no Python, FFmpeg, GPU, or speech API account on the installed host. Miro's
noncommercial model terms and attribution are documented in Admin and preserved
with its download.
