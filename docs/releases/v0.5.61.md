# v0.5.61

`/tgupdateworkers` now checks Codex runtime versions as well as worker releases,
and the Web UI displays completion instead of leaving its initial queued message
on screen.

- An explicit request checks the latest official stable Codex release even if
  today's automatic check already ran. Results report installed and running
  versions per runtime profile, the available version, and the check time.
- Supported runtime updates wait for idle workers and retain compatibility,
  integrity, readiness, and recovery checks. Pinned and externally managed
  runtimes are reported without replacing their installations. The daily
  background check schedule is unchanged.
- Worker and Codex outcomes are reported separately, so a runtime check or
  installation failure does not hide a successful worker update.
- The Web UI follows queued requests with read-only status requests and shows
  results automatically. It pauses observation in hidden tabs and stops when
  the panel is closed or the selection changes. Update requests are never
  resubmitted automatically.
- Authenticated gateway commands can be sent without selecting a session.

Codex reporting requires the new updater. A request executed by an older updater
can install this release without checking Codex; submit a new request after that
upgrade. The gateway accepts results from older workers and clearly indicates
when no runtime check was reported.
