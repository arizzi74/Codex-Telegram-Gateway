# v0.5.97

Stopped, failed internal subagents no longer indefinitely block worker updates
solely because Codex retains their `systemError` status. With new work fenced,
the worker verifies explicit spawned-child ancestry, the exact failed turn and
its completion timestamps, empty input queues, no background terminals, and
idle parents and loaded descendants. It rechecks live state before granting the
update lease. The normal update restart retires the failed child without
archiving or deleting saved history.

Active turns, pending questions and approvals, processes, hooks, compaction,
uncertain requests, and activity arriving during verification remain blockers.
Missing or unsupported evidence also blocks the update. Recovery applies only
to proven failed internal subagents; ordinary user-session errors retain their
existing protection.

Telegram and Web UI update status now explain that a pending request can be
waiting for the worker to become idle and complete its update. Older running
workers require a controlled idle restart to load the new recovery logic.
