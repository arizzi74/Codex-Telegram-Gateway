# v0.6.0

The Admin console now starts with all sections collapsed, including Telegram
bots, Audio, Sessions, Workers, Passkeys, Browser sessions and Password sign-in.
Each bot and session also has its own collapsed entry. Expansion choices survive
dashboard refreshes, and session choices survive filtering and pagination. Bot
headers keep **Enable**/**Disable** and additional-bot **Delete** controls visible;
closed sections show **Needs attention** when they contain an error.

Managed-bot creation now asks for a display name and generates a lowercase
username ending in `_bot`, such as `my_project_bot` for **My Project**. Bounded
checks cover connected bots, active creation requests across managers and public
Telegram profiles; occupied candidates receive a number before `_bot`. Lookup
failures stop creation with a retryable error. Public checks cannot detect every
reserved or unavailable name, and Telegram confirms final availability when the
owner creates the bot. Existing API clients can still submit `username` and
`name` explicitly.

New managed bots receive the bundled purple **>_ Gateway** profile icon after
Telegram confirms creation. Existing photos are preserved. Temporary photo
failures keep setup pending for callback retries, including after a restart,
while the connected bot can already handle messages. Completed setup does not
replace a photo chosen later. The creation dialog previews the icon, and its SVG
asset now has the correct Admin route and content type.

Expand an existing bot and choose **Reset profile photo >_** to apply the icon
after confirming the named bot. This includes the primary bot. Resets require
recent authentication, Origin and CSRF checks, an enabled bot, and verified
ownership, Telegram identity and gateway webhook. The reset changes only the
profile photo and reports failures for retry.

Regression coverage includes username generation, public-page validation,
reservation races and lookup limits; photo uploads, preservation and restart
recovery; reset authentication and target guards; SVG serving; and desktop/mobile
Admin flows. This release requires no database migration or new libraries.
