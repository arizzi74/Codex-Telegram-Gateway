# v0.5.63

Gateway and worker updates now retain backups for at most three previous
versions, with one complete snapshot per version. Older versions and duplicate
copies are removed only after the updated service passes its readiness check
and the new installed version has been saved. Updates that recover from a
pending readiness check apply the same policy.

Worker updates reserve the idle worker before copying backup files, so busy
retries no longer accumulate duplicate binaries. Failed updates preserve the
existing recovery history. Unrecognized or damaged backup folders are kept
with a warning for manual review.

This policy applies to gateway and worker installation backups. It does not
remove projects, conversation history, or Codex runtime data.
