# v0.6.1

Workers now recognize the Codex 0.163 read-state protocol. The
`thread/readState/changed` notification reports read/unread metadata, and a
completed `thread/readState/update` request no longer leaves an idle native CLI
connection permanently blocking worker updates.

Pending read-state mutations still block updates until their responses arrive.
A lost response remains unsafe. Active turns, approvals, processes and unknown
protocol operations retain their existing update guards; read-state messages
cannot clear those blockers.

Workers that already latched an unknown-operation blocker on an earlier release
need a controlled restart after actual work has settled. This release prevents
the read-state messages from creating that blocker in the updated worker.
